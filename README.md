# 网页控制台

替代 RViz 和 `nav.sh` 的网页界面。三栏布局：左边图层和 topic，中间地图，右边任务、运行档位、定位质量和底盘控制。

```
web/
  server/go2w_web.py   后端：rclpy 节点（域 43）+ aiohttp，HTTP 和 WebSocket 同一端口
  static/              前端：原生 JS 模块，不需要构建
    js/source/mock.js  模拟数据源（示例地图 + 机器人仿真）
    js/source/ros.js   ROS 数据源（连后端 /ws）
  prototype/           最早的单文件原型，留作对照
```

界面只读 `js/store.js` 里的状态，两个数据源负责填它；操作统一经过 `js/actions.js` 做前置检查和确认。

## 多点路线任务

1. 加载地图，点击工具栏的「导航点」（快捷键 4）。单击地图添加一站，或在站点按住拖出箭头，松开后保存箭头指向的到站朝向。右侧按顺序列出站点，可以给每站填名字。每条路线可包含 2–50 个点。
2. 用箭头调整顺序或用 × 删除点。点「确认路线」后，最后一站标为终点，只对未手动指定朝向的站点按路线推算默认方向。确认会请求 Nav2 检查站间路径，在地图上画出规划结果。可以先保存未检查的路线。
3. 输入名称并点「保存任务」。任务绑定当前地图。从列表选中后可修改或删除任务。需要运行时，从列表选中任务，在对应地图启动导航、确认定位并解锁底盘，再点「启动导航任务」。按钮下方会说明暂时不能启动的原因。
4. 出发前后端用当前位姿补算第一段，并重新检查整条路线。任何一段规划失败都不会出发。通过检查后，每站用一次 Nav2 导航，成功到达才派发下一站。任务卡片显示当前站和总站数，执行中失败会停止。

5. **循环：** 启动前勾选「循环」并填圈数。1 → 2 → … → 终点 → 1 算一圈：到终点后直接回 1 号点，不原路返回。回到 1 号点时按它自己的朝向停（自动朝向 = 面向 2 号点）。2 圈就是走两遍，下一圈从 2 号点出发；0 圈表示一直循环，直到取消。出发前检查一整圈，包括终点回 1 号点那一段。不勾选就是单程，停在终点。圈数只在启动时生效，不存进任务。
6. **从 1 号点附近出发：** 启动时离 1 号点不到 0.5 m，就当已经在 1 号点，直接去 2 号点（太短的路径 Go2W 容易卡住不动）。

网页上的 A/B 往返巡逻和地图工具栏的「导航目标」已移除（11-06），用多站任务代替：两个点加「循环」就是往返巡逻。命令行（`nav.sh`）启动的 `patrol.py` 后端仍会识别：取消、急停、切换档位时会连它一起停，它运行时网页拒绝启动多站任务。多点任务执行时，其他网页不能另发单点、巡逻或键盘遥控指令。取消、急停、上锁、控制方心跳丢失、切换地图或运行档位都会结束整条任务。连接恢复后不会自动继续。路线存在后端的 `data/routes.json`，和地图一样可单独备份。纯前端 `?mock` 的路线存于当前浏览器，没有 Nav2 规划检查。假 ROS 后端会把规划结果明确标为「本地模拟」。真实规划预览只代表检查时的地图与代价地图，执行中仍由 Nav2 根据最新障碍物重规划。

本地可用 `web/dev/run.sh` 启动假机器人，再运行 `node web/dev/test_routes.mjs` 验证多点协议和停止行为。真机验收时要检查实际到点、朝向和停车。

## 右栏任务流程（11-06）

右栏顶上是三个任务：**导航 | 重定位 | 建图**。点标签就是真的切换档位，切换时一律先停车（取消任务、底盘上锁）。原型见 `prototype/right_panel.html`。

- **导航**：没在跑时弹框选地图、确认站立静止，确认后直接启动导航。之后按五步走：地图 → 初始位置（用「初始位姿」工具，或确认 AMCL 当前位置正确）→ 导航任务（只列当前地图的任务，新建 / 编辑沿用原来的路线编辑器）→ 运行参数（循环、最大 vx / wz）→ 启动。「启动导航」弹确认框列出这次的设置，确认后后端先解锁再出发（`route_start` 带 `arm: true`，出发失败会把锁再上回去）。
- **重定位**：导航在跑时不重启导航栈，只取消任务、上锁；导航没在跑时启动「定位」档位。在 AMCL 当前估计的基础上手动微调：方向键按屏幕方向平移、Q / E 旋转（步长 1 cm·0.5° / 5 cm·1° / 20 cm·5°），或在地图上拖青色机器人平移、拖车头圆点旋转。激光按修正后的位姿重画，贴墙绿、悬空红，匹配率在前端实时算（和后端一样，离墙 0.10 m 内算对上）。点「应用到 AMCL」才发出，用小协方差（σ 5 cm / 2°，`initial_pose` 带 `cov: "fine"`）。有没应用的改动时离开会先问。偏得太远时用「重新给位置」走普通初始位姿。
- **建图**：确认站立静止后停掉导航、启动建图。五步：建图中（运行时长）→ 遥控走一圈（可勾选同时录包）→ 地图对齐（可选，从底部抽屉挪过来）→ 保存地图（默认名 `lab_年月日`，后端不覆盖同名，保存后自动换成 `_2`、`_3`…）→ 结束：「用这张图去导航…」（弹框里默认选刚保存的图）或「停止建图」。没保存就离开会提醒。底部抽屉「地图与录包」只留地图列表和录包管理。
- 原来的「运行档位」卡片只在调试模式显示。

## 摄像头

地图区里的摄像头浮窗显示 Go2W 前置摄像头：地图右上角按钮列最下面的摄像头按钮打开 / 关闭（默认关着），标题栏 ✕ 关闭；拖标题栏移动，拖右下角按画面比例缩放，双击右下角恢复默认（左下角、宽 320 px）；位置和大小记在本机浏览器 `localStorage` 的 `go2w.camWin`。只在浮窗开着且浏览器标签页在前台时传画面。主控 `192.168.123.161` 在机器狗内网组播 `230.1.1.1:1720`，格式为 RTP/H.264，1280×720，约 14 帧/秒，约 1.5 Mbit/s，约每 2 秒一个关键帧（11-06 在扩展坞上实测）。后端在扩展坞有线口上接收，只把 RTP 拼回完整帧，不解码，再经 `/ws` 原样转发。浏览器用 `js/vendor/jmuxer.min.js`（jmuxer 2.0.7，MIT）封装成 MSE 播放，http 页面就能用。

- 只有这个标签页开着、底部面板展开、浏览器标签页在前台时才传输。切走后后端退出组播，不再收任何数据。
- 同一时间只给一个网页传画面。别人在看时显示对方 IP，可以点「接管画面」。
- 打开后最多约 2 秒出画面（要等下一个关键帧）。网络跟不上时，画面会跳到下一个关键帧，延迟不会越积越多。
- 拖高底部面板可以看大一点，面板高度会被记住。
- 后端的接收地址和网口可以用环境变量 `GO2W_CAM_ADDR`（默认 `230.1.1.1:1720`）和 `GO2W_CAM_IF`（默认 `GO2W_WIRED_IF`）修改。

本地调试：`web/dev/run.sh` 会启动 `dev/fake_camera.py`，循环回放真机录的 10 s 样本 `dev/camera_sample.rtp`。测试：`web/dev/test_camera.py`（拆帧，装了 ffprobe 会独立解码核对），`web/dev/test_camera_ws.py`（协议，要先运行 run.sh）。

## 地图显示方向

建图时地图的 x 轴取机器人开始建图那一刻的朝向，所以有的图是斜的、有的是竖的。这不影响定位和导航（Theta* 能走任意角度的直线），只是看着别扭。网页可以按地图单独保存一个**显示方向**：只转画面，不改地图坐标，所以路线、巡逻点、初始位姿都不用重做。

- **自由旋转：** 按住 Shift 拖动地图，或按住右键拖动，地图绕画面中心转。靠近 0° / 90° / 180° / 270°（±3°）会自动吸附，按住 Alt 不吸附。
- **指南针按钮：** 在地图右上角，红色针尖指向地图坐标的 +y 方向。单击顺时针转 90°，双击复位到 0°。
- **精确对齐：** 在「地图与录包」面板点「沿墙选两点」，选同一段长直墙上的两个点（至少 0.5 m，推荐 1 m 以上），可切换「对齐水平 / 对齐竖直」；「复位方向」回到 0°。
- **保存：** 松开鼠标后存到扩展坞的 `data/map_views.json`，按地图名记录，0° 不记录。从 166 和 142 打开、换哪台电脑看到的都一样，有人改了其他网页会跟着变。切换地图时自动换成那张图的方向，断线重连、切换档位不会清除。
- **建图时：** 还没有地图名，方向先暂存在 `_mapping` 下。「保存当前地图」时带给新地图。
- 地图、机器人、点云、路线、目标一起旋转，背景网格保持水平；鼠标点击换算回地图坐标，位姿读数仍是地图坐标。键盘遥控 W/S/A/D 相对机器人本身，不受影响。

**导出对齐地图（一般不需要）：** 建图运行时，输入新地图名并点击「保存对齐地图」。后端先保存原图及 SLAM 数据，再按当前显示方向把图片转正，生成 `<名字>_aligned.pgm/.yaml/.png`，都位于扩展坞的 `~/go2w/data/maps`。图片最多转 ±90°，剩下的 180° 记成新地图的显示方向。对齐副本的坐标和原图不同：用它导航要重新设置初始位姿、重新选路线站点。原图保留用于续建。导出失败时原图保留，可以重试；已有文件不会被覆盖。只在需要地图文件本身是正的时候才用（比如给 RViz 或别的工具）。

`web/dev/test_map_alignment.py` 验证图片旋转、原点和未知区域；本地假 ROS 页面也会运行相同的导出程序，可在未连接机器狗时检查保存结果。

### P2 图层的数据来源

| 图层 | 来源 | 处理 |
|---|---|---|
| 全局代价地图 | `/global_costmap/costmap`（map，1 Hz） | 内容没变不重发 |
| 局部代价地图 | `/local_costmap/costmap`（odom，6×6 m，2 Hz） | 经 TF 转到 map 再叠加 |
| 点云 | `/cloud_registered_body` | 转到 base_footprint，只留离地 0.3–1.6 m、12 m 内的点，5 cm 俯视体素，每帧最多 4000 点，最多 5 Hz |
| 全局路径 | `/plan` | 最多 500 点；只在任务进行中显示 |
| 局部轨迹 | `/cmd_vel` | MPPI 的 `visualize` 是 false，所以按实际下发的速度指令外推 1.6 s，不是 MPPI 的最优轨迹 |
| MPPI 采样 | — | 真机上没有（要在 nav2.yaml 打开 `visualize`，明显多占 CPU 和带宽） |
| AMCL 粒子 | `/particle_cloud` | 最多 300 个，2 Hz |
| 日志 | `/rosout` | 转发 INFO 及以上，每秒最多 30 条，超出会提示丢了几条 |
| 定位质量 | `/amcl_pose` 协方差；scan 点落在地图障碍物 10 cm 内的比例 | |
| 姿态 | TF `base_footprint → base_link`（planar_odom 用机器人 IMU 发布） | |

点云、两张代价地图和粒子只有在有网页打开对应图层时，后端才计算和发送。本地测得全部图层打开时约 60 KB/s（真机点云更密，估计最多再加 150 KB/s）。

### P1 的安全规则

- **急停**：取消所有导航目标（包括 RViz、patrol 发的）并调用 `/go2w_cmd_bridge/arm(false)`，cmd_bridge 会立即发 StopMove 并上锁。急停是锁存的：解除之前拒绝解锁和发目标；急停期间如果底盘被别处（比如 `nav.sh arm`）解锁，后端会再次上锁。解除急停后底盘仍保持上锁。
- **心跳**：网页每 0.5 s 发一次心跳（放在 Web Worker 里，切换浏览器标签页不会误触发）。最近一个发过运动相关指令（解锁、目标、取消、急停）的网页是「控制方」。控制方心跳超过 1.0 s 或网页关闭时，如果底盘解锁着或有导航目标，后端会取消导航并上锁，恢复后也不会自动解锁。超时时间用后端参数 `--heartbeat` 调整。
- 后端（`go2w_web` 容器）本身挂掉时没有人替它上锁：Nav2 和 cmd_bridge 会照常运行，这时请用遥控器。
- 暂停在真机上不支持（Nav2 没有暂停），用取消或上锁代替。

## 上机检查清单（统一部署时）

本地假 ROS 验证的是界面、协议和安全逻辑；下面这些只有真机能确认：

P3（`docker exec` 走的是真实 Docker API，本地只用假 socket 测过）：

21. `nav.sh status` 看到的状态和网页一致；用 `nav.sh start` 启动的导航，网页也能识别并停止

### P3 的注意事项

- `go2w_web` 挂了 `docker.sock`，等于后端能控制扩展坞上的 docker。后端只执行 `web/server/procs.py` 里固定的命令，地图名、包名、topic 名都经过校验。
- 网页没有登录：同一网络里能打开页面的人都能启停导航、解锁底盘。只在可信网络里用。
- 多站任务和遥控都受心跳保护：关掉发起操作的网页会停车。长时间执行任务时要保持网页开着。
- 遥控直接发布 `/cmd_vel`，开始前会取消导航并拒绝同时发目标；没有加速度指令复用器，RViz 此时再发目标会和遥控抢指令。

测试：`node web/dev/test_protocol.mjs`（P1）、`node web/dev/test_p3.mjs`（P3）、`node web/dev/test_map_views.mjs`（地图显示方向）都要先运行 `web/dev/run.sh`；`web/dev/test_procs.py` 用假 Docker socket 真实执行进程管理脚本。

每一项都手持遥控器做，先在空旷处、低速（滑条调到 0.3 m/s）试。

## 回溯录制

录包区的「回溯录制」打开时（默认打开），建图 / 定位 / 导航运行期间，`scripts/rollback_recorder.py` 把最近 20 秒的数据留在内存里循环覆盖，不写硬盘；点「保存刚才 20 秒」存成 `data/bags/snap_<时间>`，和普通录包一样可以上传、删除。topic 是默认录包列表加 `/livox/lidar /livox/imu`（`procs.py` 的 `ROLLBACK_TOPICS`）。它是独立进程、独立节点，可以和 `ros2 bag record` 同时运行。`/map`、`/tf_static`、`/robot_description` 这种只发一次的 topic 会一直保留，放在包的开头。日志在 `data/logs/rollback.log`，开关状态在 `data/rollback.json`。

## 部署到扩展坞

第一次部署需要重建镜像，因为加了 `python3-aiohttp`；之后只改网页代码的话，同步后刷新浏览器就行，后端代码改了要重启 `go2w_web` 容器。改了 compose（比如 P3 加的 `docker.sock`）要重建这个容器：`docker compose up -d --no-deps web`。

1. 同步代码 · 在 Mac 上运行：

   ```bash
   ~/Desktop/go2w/scripts/sync.sh dock
   ```

2. 重建镜像并启动网页服务 · 在扩展坞上运行：

   ```bash
   cd ~/go2w/docker && docker compose build ros && docker compose up -d --no-deps --remove-orphans web
   ```

   `--no-deps` 保证不会重建正在跑导航的 `go2w_humble`；`--remove-orphans` 会删掉已经不用的 `go2w_foxglove` 容器。

3. 打开网页 · 在 Mac 浏览器里：http://192.168.1.142:8080

## 常驻服务器入口（192.168.1.166）

大家平时打开 **http://192.168.1.166**。166 上的 nginx 提供前端页面，并把 `/ws` 转发到扩展坞的 `192.168.1.142:8080`。后端、心跳上锁和进程管理仍在扩展坞上，166 只做转发。机器人关机时页面仍能打开，但只显示「机器人未连接」，开机后自动重连。直接打开 `http://192.168.1.142:8080` 也照常能用。

- 第一次安装（已完成 11-05）· 在 166 上运行：`sudo bash ~/go2w-web-setup/install.sh evoengine`（文件来自 `scripts/server/`）。安装 nginx 并设为开机自启，放行局域网访问 80 端口，禁止系统休眠。
- 改了前端 · 在 Mac 上运行：`scripts/sync.sh server`。前端在扩展坞上也有一份，要保持一致。
- 后端只信任来自 166 的 `X-Forwarded-For`，日志显示为「真实 IP 经 192.168.1.166」。代理地址可以用环境变量 `GO2W_TRUSTED_PROXIES` 修改，多个地址用逗号分隔。

看后端日志 · 在扩展坞上运行：

```bash
docker logs -f go2w_web
```

只改了后端代码时重启 · 在扩展坞上运行：

```bash
docker restart go2w_web
```
